## 6. /works 実績の表現

現状：抽象化済み（社名は出していない）。

**社内承認後に強化するなら：**
- 案件規模・工期・パートナー数を数字で記載
- 「課題 → 介在 → 結果」のケーススタディ三段構成へ
- 「もしモモヤがいなかったら」の仮想損失額を併記（インパクト大）

ストーリー化テンプレ：
```
[課題]
ゼネコンA社の3階フロア改修で、電気の打合せが2週間止まり、図面が確定しない状態。

[モモヤの介在]
週2回の現場常駐打合せ。施工図を3日で起こし、設計図と整合。
材料はメーカーから直調達でリードタイムを2週間短縮。

[結果]
工期：当初予定より3日早く完工
原価：材料費 ▲5%（〇〇万円）
追加工事：ゼロ
```

## 9. 公開後 改善PDCAの観点

- **`/why` 直帰率 > 50%** → 業界課題が抽象的すぎる。具体的な事例数値を追加。
- **`/value` までの到達率 < 30%** → トップでベネフィットが伝わっていない。C案（利益保全型）にA/B切替。
- **お問い合わせCV率 < 1%** → CTA文言と位置を見直し。フォーム項目数を減らす（最小：会社・名前・メール・本文）。
- **東京/大阪の地域分布** → 東京流入が想定より低ければ、`/contact` の地域選択初期値を東京に。
- **滞在時間 `/value` < 30秒** → インフォグラフィックが読まれていない。スクロールアニメで段階開示。

## 10. 文言レビューの優先順位

社長・豊嶋様レビューでまず確認したい3点：

1. **「打ち合わせ屋／実務番頭」の社外露出強度** — 現在トップページでフルに使用。控えめ表現に戻すかの確認。
2. **数値の正確性** — 「パートナー50社+」「20年」「全国対応」は事実か精査。
3. **法的・契約的に書けない情報の確認** — 過去案件の実名（小池都知事視察案件 等）を `/works` でどこまで書くか。
